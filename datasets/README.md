# 合成数据与证据边界

`python -m datasets.generate --output .local/datasets` 生成 480 个任务：48 个采购、往来及期间检查的拓扑/故障配置，每配置 10 个变体；两套制度各 240 个任务，场景族按 30/8/10 分入开发、验证、封存测试集。

这些是**合成配置，不是 48 个真实行业或独立采样企业**。同一族的全部金额和制度变体位于同一集合。当前测试集仍可能与开发集共享故障类型，不能解释为对完全未知会计业务的泛化验证。

- `observed/` 是调查服务可见输入。
- `on_demand/` 是按需释放的证据，不能直接出现在旧快照。
- `truth/` 只由评测进程读取，Docker API/Worker 不应挂载该目录。
- `manifest.json` 保存版本、场景结构、分组及观察数据哈希。

金额和事件由 Python 整数生成，不使用生产会计引擎计算标签。标签来自显式故障注入。包含正常分批、反向冲销、已确认重复、未收到资料、冲突来源以及**可见资料相同而隐藏原因不同**的不可判定情形。

本地文件分区是开发隔离方式，不是面向恶意本机用户的安全边界。封存集在正式评测期间还应由独立进程账户或外部保管方管理。仓库只分发生成器，不把运行生成的数据当成真实企业资料。
