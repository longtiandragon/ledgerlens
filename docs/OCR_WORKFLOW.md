# 扫描件人工核实与导入

2026-10-13。数据接入页已接入独立本地 OCR：上传 PNG/JPEG/扫描 PDF → 查看未确认文字及原件位置 → 人工填写字段并关联原文行 → 保存复核版本及导入预览 → 明确确认导入 → 生成业务记录与新快照。没有付费模型调用，没有自动字段推断或自动入账。

## 数据边界

- 原件按 SHA256 保存；读取、复核及导入前核验字节。文字观察始终为 `unconfirmed`，人工确认另存 `ocr_reviews`，不改写 OCR 输出。
- 每个非空业务字段必须关联当前任务成功页面的观察 ID。日期和金额也必须由人填写；金额遵循原 `LedgerInput` 的 Decimal 字符串契约。来源编号、记录类型、期间和币种由人工确认，后两项必须匹配账套。
- 每次字段修订追加版本，带父版本、原件/结果哈希、账套政策版本及数据修订号。并发旧表单被拒绝，较新复核使旧导入预览失效；账套改变也使旧预览失效。已导入记录不能覆盖。
- 导入预览保留逐字段页码、行号及多边形。确认导入沿用普通导入事务、来源冲突检查和快照逻辑；快照中的记录继续引用原始文件。OCR 预览禁止绕过复核改列映射。
- 后台执行固定脚本及服务端配置的独立解释器，不接受请求提供 Shell 或程序。子进程不继承 DeepSeek 密钥；现有 OCR 脚本拒绝网络连接。没有将评测答案交给识别进程。
- 产品上传限制 20 MiB；PDF 仍有 20 页、每页 1600 万和总计 8000 万像素预检。单进程串行识别，最多四个排队/运行任务；超时默认 180 秒、有效范围 10–600 秒。此队列仅支持本地单进程，容器/Celery 模式不启用 OCR。
- 空白页不能生成字段确认；失败页保留失败，不成为引用。服务重启将中断任务标记失败，过期 worker token 不能回写结果；原件仍保留，可重新上传建立任务。

## 本地启用

沿用已验证的可选环境与固定官方权重，准备方式和许可证见 [OCR_VALIDATION](OCR_VALIDATION.md)。没有向主 API 环境增加生产依赖。

```powershell
# 若已有本项目本地服务，先按所记录 PID 与启动时间停止。
& scripts/stop-local.ps1
$env:OCR_PYTHON = (Resolve-Path '.local/ocr-env/Scripts/python.exe').Path
$env:OCR_MODELS_DIR = (Resolve-Path '.local/ocr-models').Path
& scripts/start-local.ps1 -SkipInstall
```

缺少配置时网页显示未启用，上传返回 503；路径存在但环境/权重不匹配时任务明确失败。启动脚本使用的本地 `create_all` 会增加新表；部署的 Alembic 冻结迁移新增 `0005`，只向前迁移。迁移测试覆盖从 `0004` 保留已有原件行升级，禁止破坏性降级。后续已在真实PostgreSQL临时schema补验0004→0005→0006，原件、快照、OCR观察及人工复核保持，见[迁移补验](REFERENCE_WORKFLOW.md#postgresql-迁移补验)；没有执行生产部署。

## 已执行验证与限制

后端定向检查覆盖保存复核前不生成记录、确认后的原件定位/快照、重复导入幂等、字段引用范围、浮点金额、非布尔确认、账套变化、原件/文字/定位/预览篡改、旧版本、空白/失败/部分失败、重启租约及队列上限。测试替身只用于工程边界，不计作 OCR 准确率。

浏览器使用真实本地 CPU OCR，分别上传 `scan-001.png` 和六页纯图像 `synthetic-scans.pdf`。从第一张合成采购单人工确认日期 `2026-09-12` 与价税合计 `1394.99`，每份原件导入一条采购记录。核验原文件字节一致、快照包含该记录、字段保存前后记录数分别为 0/1、OCR 原始结果仍未确认、已导入字段不可覆盖；另核验 PDF 第六页空白、原文高亮、390px 布局及浏览器无错误/无调查请求。

早期验收失败也保留：`runtime/ocr-e2e-v1` 中图像已完成导入，但测试错误读取扁平 `/records` 为嵌套对象；金额预期未改。PDF 页码选择补充明确的可访问名称。`v2` 因本地服务停止而连接拒绝；确认服务已停止后重启，`v3` 两项通过（49.8 秒）。`ocr-all-e2e-v4` 全量 41 通过、1 失败：原 CSV 上传测试使用泛化文件选择器，新增 OCR 文件控件后发生歧义；两个入口赋予明确名称并按入口定位，原错误隔离和金额预期不变。最终全量验收与来源摘要见 [ocr-workflow-validation.json](ocr-workflow-validation.json)。桌面和手机截图保存在各次验收目录。

最终后端全量1917通过、2项Windows文件链接权限跳过（111.10秒），浏览器全量42通过、0跳过（2.2分钟），类型检查/生产构建、Ruff和生成契约一致性通过。摘要读取原API JSON字节后核验结果指纹与所有文字坐标；JavaScript重序列化会把 `1.0` 写成 `1`，因此浏览器解析后的对象不能单独作为哈希复核原件，另行保留原响应。

该验证只证明有限合成样本的产品流程。原有六图/六页 OCR 的字串 23/24、整行 28/35 及字符混淆错误仍然有效，没有因人工修正提高识别准确率。每次复核仅一条记录，网页每字段选择一条原文行；扫描表格行列重建、多记录提取、真实单据、手写识别、专业会计复核和多用户审签仍未完成。
