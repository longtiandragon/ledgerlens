# 参考语料的来源与内容绑定

`reference-corpus-v2` 用于防止采集报告、解析路径或检索产物误改后，把评测答案或无关文字贴上合法政策来源标签。它不增加可执行会计规则，也不判断资料的现行法律效力或专业适用性。

## 已确认的问题

旧构建器仅排除 `official_answer` 和 `case_index`，其余类型默认读取报告中的 `parsed_path`。独立只读检查确认：把答案类型改为 `policy`、删除类型、使用未知类型，或保留合法政策元数据但替换解析路径，都可能把答案文字放入检索结果。检查没有写入实际语料；当时实际13个片段仅来自规范通知及完整附件，原件与重解析内容核对一致，未发现实际污染。

因此，“正常标记的答案已排除”不能证明错误标记或内容替换也会被拒绝。资料目录分离也不是对可同时改写登记、原件、数据库和摘要的本机用户的操作系统权限边界。

## 绑定与加载

可信来源登记位于 `docs/data-sources.json`，与可变的采集报告分开。运行使用登记的 ID、类型、URL、制度、标题和声明生效日期，只有 `policy`、`policy_notice` 能进入参考语料。官方答案、案例目录和组件评测材料明确排除，缺失或未知类型不默认变成政策。

登记中的 `required_text`、`expected_article_title` 若明确配置，也参与内容核对。规范通知的原始文章标题由归档原件定位，并与展示别名区分。HTML中明确的问答/评测标志还会拒绝，但该检测不是能够识别所有答案文本的语义分类器。报告自报的publisher或redistribution不进入受信运行声明。有效期结束尚未支持，登记或报告提供非空 `effective_to` 时拒绝，而非默认为一直有效。

构建时限定来源目录及文件位置，拒绝越界与链接替换；对有界读取的原件字节计算SHA-256，并从同一字节内容重解析HTML或PDF。解析产物必须与重解析内容一致。语料记录原件、规范化解析、片段及来源绑定的摘要、页码和字符位置。HTML正文和PDF文字都是参考文本，不自动成为结构化会计事实。

实时检索和创建快照都调用同一个 `load_verified_corpus`，重新校验登记、原件、解析产物和全部片段，然后使用已验证的内存副本。不能先校验文件再从路径重新读取一个可能已经变化的内容。纯 `search(list)` 是内部检索计算函数，调用它本身不证明传入列表经过来源校验。

新文件为 `runtime/knowledge/corpus-v2.json`。旧 `corpus.json` 保留，不自动升级或混入新检索。没有新语料时，接口明确返回 `not_configured` 或 `legacy_unverified`；有新版文件但校验失败时返回409，不能伪装为成功的空检索。

## 固定快照与模型入口

新快照将参考文字及 `source_binding` 一起固定，并标记 `reference_integrity`。来源绑定保存原件、解析和片段身份；冻结片段自身的展示字段也受摘要约束。

模型调查入口与后台任务都在构造模型网关之前检查非空参考片段。旧快照若只有未绑定文字，将拒绝新的模型调查；历史记录与底稿仍能查看。后台重投同样执行检查，失败后保留原因并释放运行槽。空参考列表可以继续调查，代表没有提供参考文本，不代表已验证所有政策。

冻结片段的内部核验不重新读取如今的原件，避免用后来变化的资料改写历史上下文。它证明内容与既存摘要和登记身份一致，不能单独证明来源的真实性、当时已获知、完整防篡改或现行效力。后续修改整个可信登记可能使旧片段无法用于新的模型运行；旧结果仍保留。

当前调查身份升级为 `investigation-v20` / `snapshot-tools-v10`，明确记录来源绑定策略。账务 `domain.py`、`matching.py` 与执行规则身份没有随检索策略改写。先前v19及更早的实测和失败记录仍属于各自版本，不能转记为v20模型验收。

## 已执行验证

80项独立来源测试与25项独立运行入口测试通过。手写原件、预期文字和临时登记与正式资料分开；实际HTTP、快照、`retrieve_policy`及Worker拒绝路径都执行。Windows真实符号链接创建被拒绝，相关检测使用明确标记的模拟条件；不宣称已验证实际操作系统链接隔离。

两个实际归档来源重建13个片段，原始文件及旧语料保持不变。真实服务11项流程验收通过，新合成账套冻结10个匹配参考片段，13条原始账务记录不变，模型请求0次。首轮报告因后台任务尚未终态而失败，记录保留；新增有界等待后的第二份报告通过，没有修改财务预期。完整后端1506通过、2权限跳过，浏览器31通过、0跳过；这些结果不证明v20真实模型能力、全部准则或企业业务效果。

## 复现

```powershell
.venv\Scripts\python.exe scripts/index_sources.py
.venv\Scripts\python.exe scripts/validate_knowledge_runtime.py --output .local/reports/knowledge-runtime-new.json
.venv\Scripts\python.exe -m pytest -q backend/tests/test_knowledge_provenance.py backend/tests/test_knowledge_runtime.py
```

索引构建只读取本地已取得原件，不发起模型请求。实时API验收会创建明确标记的合成测试账套，检查检索、固定快照、规则调查和原账只读。选择新的报告文件名，已有验收记录不能覆盖。实际测试数量和模型可用性以[交付状态](STATUS.md)记录为准。
