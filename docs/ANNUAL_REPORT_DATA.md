## 官方来源与保存方式

- `docs/annual-report-sources.json` 固定证券代码、公司全名、报告年度、公告 ID、公告标题、公告日期、官方查询地址、公告详情地址及原始 PDF URL。30 条记录均与已保存的巨潮官方查询响应中的公告 ID、证券代码和 PDF 地址匹配。
- 发现来源使用巨潮资讯公开接口 `https://www.cninfo.com.cn/new/hisAnnouncement/query`；下载仅接受 `https://static.cninfo.com.cn/finalpage/.../*.PDF`。来源清单在下载前落盘，排除摘要、英文版和非年度报告公告；不会绕过登录或验证码。
- 原始 PDF 只放在被 Git 忽略的 `.local/annual-reports/raw/<证券代码>/<年份>/<SHA256>.pdf`。此处使用已有 30 份成功传输的原件进行复核，未重复下载。
- `.local/annual-reports/metadata/` 保存官方证券组织标识和逐公司查询参数、响应与抓取时间；`.local/annual-reports/acquisition-report.json`、`acquisition-history.jsonl` 保存本地采集结果与逐次历史。
- 可提交的 `docs/annual-report-coverage.json` 保存每份报告的原始/最终 URL、证券代码、公司名称、年度、SHA256、字节数、许可状态、解析器版本、页数、封面身份与报表页证据；其 `source_manifest_sha256` 固定所用来源清单，报告内容由各自的 SHA256 固定。

公开披露不等于许可再分发。当前每份原件均标为 `license_status: unspecified`，未确认再分发许可，因此仓库不分发原 PDF；仅提交来源与核验元数据。没有新增依赖，也没有模型调用。

## 筛查条件与复核结果

采集器 `datasets/annual_reports.py` 使用 `annual-report-pages-v2`，最多两个下载/校验任务并发，每份最多 35 MiB、600 页。下载拒绝越出官方允许列表的跳转，检查 PDF 文件头与传输末尾标记。原件按内容哈希保存；续跑先核对本地路径、身份、字节数与 SHA256，完整但尚未通过筛查的原件也会复用。

文档筛查需要 40—600 页、封面中的公司全名与对应年度完整年度报告标题，并排除摘要。随后在真实 PDF 页面定位三张基本合并报表：资产负债表、利润表、现金流量表。每张需独立表头、对应年度、金额单位及至少两种典型表行的多列数字；目录中的页码和附注里的文字提及不算报表。允许人民币元或千元的整数列示、明确含合并列的“合并及公司”表格，以及至多后续两个页面的续表。遇到母公司或其它报表表头时停止借用后续行。

v1 曾漏检苏宁易购和用友网络的六份原件，因为部分报告以整数列示金额，苏宁 2023 年使用“合并及公司”标题，用友 2025 年现金流量表标题与数字行分居相邻页面。v2 对全部 30 份既有原件重新执行筛查，实际结果是 30 份通过、0 份下载未验证、0 份失败或待处理；`offline: true` 且 `reports_requested_in_this_run: 0`。报表页码为从 1 开始的物理 PDF 页码，涉及续表时另记录 `checked_pdf_pages`。

这些检查确认来源身份与报表内容位置，不核算表内金额、不判断审计意见，也不保证所有页的语义都已审阅。没有 OCR、扫描版泛化、结构化表格抽取评测或模型问答评测结果。业务事实仍须从固定快照中进行独立抽取和复核。

## 可复现命令

在项目根目录已有依赖环境中执行：

```powershell
# 新采集时先发现并保存官方来源；此步骤访问公开巨潮接口。
.venv/Scripts/python.exe -m datasets.annual_reports discover

# 按固定来源采集；完整本地原件会复用，最多两并发。
.venv/Scripts/python.exe -m datasets.annual_reports collect --workers 2

# 当前 30 份原件的复核命令，禁止请求 PDF。
.venv/Scripts/python.exe -m datasets.annual_reports collect --offline --workers 2

# 独立离线回归与静态检查。
.venv/Scripts/python.exe -m pytest backend/tests/test_annual_reports.py -q
.venv/Scripts/python.exe -m ruff check datasets/annual_reports.py backend/tests/test_annual_reports.py
```

本次独立回归 **35 passed**，Ruff 通过。手写输入覆盖官方地址限制、公告日期时区、摘要/错误公司/错误年份拒绝、目录与附注拒绝、整数与括号负数、组合合并表头、跨页表头、续页范围与母公司表隔离、已下载未验证原件复用、解析器换版重新筛查、本地原件被修改或缺失、非 PDF/截断响应、解析异常、外部跳转和并发上限。回归不访问网络，不使用生产代码生成财务标准答案；测试没有验证财务数值或模型能力。

发现不完整或采集未全部通过时 CLI 返回非零状态（覆盖未完成为 2），并明确保留失败、待处理或下载未验证状态。`--offline` 下缺失或被修改的原件标为失败，不发起替代下载。更新来源或原件后，应重新固定来源清单和内容哈希，并复核相应结果。
