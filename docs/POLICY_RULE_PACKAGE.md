# 财政部归档问答的一致性规则包

当前版本为 `policy-consistency-v5`，33条规则（CAS 31／SCAS 2）覆盖全部32份归档问答，191个手写开发投影通过。下文保留v1至v4的历史覆盖记录，v5新增13条及其人工判断边界见文末。组件接收已经由人确认、带原始来源引用的业务条件，检查当前处理是否与归档问答一致。它不自行判断资本化、经济利益或原费用化正确性，不读取评测答案目录，也不使用模型完成这些判断。

本组件已通过独立账套 HTTP 接口保存条件版本、执行检查和导出结果，不改变现有账务规则 `0.1.0` 的执行身份。已通过固定运行上下文接入只读政策调查工具；调整模拟和复核审批尚未接入。见[调查政策上下文](INVESTIGATION_POLICY_CONTEXT.md)。下面的覆盖范围不能推导为两套准则的完整支持、真实账套的准确率或专业有效性验证。

## 输入与边界

`PolicyObservation` 与 `PolicyCheckContext` 定义在 `backend/app/policy_contract.py`。条件值采用 `yes/no/unknown`，只有 `human_confirmed` 的确定值用于规则分支。`source_reported`、`model_suggested`、`unconfirmed` 都保留为未知条件，不修改原始输入。

已确认条件、已确认受益对象及已知当前处理必须提供证据标识。调用时再次校验所有引用是否属于同一账套、同一快照，且上下文证据的获知时间不能晚于调查截止时刻。即使某个引用用于未确认条件，它也必须通过范围校验。结果的 `evidence_ids` 是全部已绑定输入引用的去重排序列表，引用存在本身不代表其内容可信。

纯组件的上下文由内部调用方传入；Pydantic 校验本身不是证据权限证明。HTTP 接口不接收 `PolicyCheckContext`。服务端读取 `Snapshot.policy`、`Snapshot.created_at` 和真实 `Record` 成员构建上下文，核验记录身份、获知时刻、规范化来源指纹和快照摘要，拒绝客户端自报框架、时间或证据成员。

每个被引用的来源文件重新核验内容哈希，再按已确认 `ImportBatch.mapping` 重解析 JSON／CSV／XLSX，核对同一来源编号、类型、第一条对应原始行定位和规范化记录指纹。不存在确认导入、定位指向别行或来源存在冲突时拒绝执行。这不验证合同内容真伪，亦不是对可同时篡改全部本地文件、数据库和哈希的攻击者的完整防篡改证明。

重新校验用于防止 `model_construct` 或冻结模型内的可变容器绕过约束，不会修改输入、创建分录、修改账簿、运行任意代码或查询答案库。政策身份由本包和契约源码在模块载入时计算，规范化换行后包含文件名与内容哈希；新源码载入产生新的身份，不覆盖旧执行身份。

## 四种输出

- `normal`：条件充分且当前处理与这条有限规则一致。
- `supported`：条件充分，当前处理与有限规则不一致；仅支持该具体差异。
- `insufficient`：必需条件尚未确认，或缺少当前处理；`missing_conditions` 使用契约的字段名。存货确认条件明确不满足时也保留判断，不自动费用化。
- `unsupported`：制度不匹配、资本化/其他业务路径超出范围、多个收付事件未拆分，或参考资料当时不可见。

已确认全部条件但缺少当前处理时，可以保留 `expected_treatment` 的条件化建议，同时状态为 `insufficient`。未知条件时不提供确定的预期处理。所有结果包括归档来源、条款定位 `div.TRS_Editor`、本包版本及源码指纹。

## 当前限制

不生成确认事实，不判断证据真伪、重要性、资本化资格或税收资格，不计算相关金额，不适用于未列明的业务处理路径。对于原费用化有误的样机，须进入独立的差错更正规则；该问答不能用来永久保留原错误。对于同时收到与缴回的退税，须拆分现金流事件，不能净额归类为其中一个方向。CAS 与 SCAS 的现金流项目保持各自的依据和测试。

覆盖与评测结果由独立基准报告记录。规则编译依据来自六条公开问答，基准中的人工预期与对比案例属于评测程序；运行 Agent 不应索引这些评测答案。其余26条已采集问答尚未由本包实现。专业复核、真实账套业务验证及准则后续替代情况核验仍是后续工作。

## 版本、接口与历史结果

`policy_observation_versions` 和 `policy_check_runs` 独立存储，不冒充既有 `Case`、`CheckRun` 或 `Review`。同一账套、快照和业务观察键按父版本追加；旧版本、评论和确认时间不覆盖。观察摘要覆盖全部版本链元数据和内容，结果摘要覆盖输出、绑定及执行身份。历史读取也核验内容和绑定一致性。

人工确认表示本机用户**现在对冻结来源的判断**。`source_cutoff` 是原始记录可见截止时刻，`annotation_recorded_at` 是人工条件录入时间，两者分别输出；不能宣称这些人工判断在原始历史时点已被系统获知。本地用户确认尚无身份鉴权或专业资质认证。

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/policy-checks/catalog` | 六条规则、条件、来源和规则包身份 |
| `GET/POST /api/v1/books/{book_id}/policy-observations` | 按真实快照保存、查询条件版本；POST必须显式人工确认 |
| `GET /api/v1/books/{book_id}/policy-observations/{id}` | 查看具体版本、是否被替代及截止时刻 |
| `POST /api/v1/books/{book_id}/policy-observations/{id}/check` | 固定该条件版本和规则包，幂等保存检查结果 |
| `GET /api/v1/books/{book_id}/policy-checks` | 分页查询已保存的检查，可按快照或观察版本筛选 |
| `GET /api/v1/books/{book_id}/policy-checks/{id}` | 校验后读取历史结果 |
| `GET /api/v1/books/{book_id}/policy-checks/{id}/export` | 导出JSON绑定、条件、结果和来源定位 |

新条件版本、账套资料变化或规则包身份变化使旧结果显示 `stale`。过期条件版本不能继续执行新检查；历史结果保留原始结论及来源元数据，不用新版规则悄悄重算。重新执行须通过当前来源校验。政策条件不会修改 `Book.revision`、既有账簿或旧政策指纹；既有调查和审批状态不由这个独立模块代替。

## 独立开发基准

当前[公开验证元数据](official-policy-validation.json)记录：32对已获取原文／题目／答案重新核验，选择其中六条来源；30个手写结构化投影全部通过，分为10个规则场景和20个处理错误、未知条件或不适用路径的变体。CAS 22个、SCAS 8个。**不是30条官方案例，也不是32条准则全部通过。**

标准结果为评测程序中人工编写的文字标签，未调用生产规则生成；模型请求0次。运行组件只接收条件和来源标识，不接收完整官方答案、基准预期或封存测试真值。基准属于公开开发资料，不是未知测试集，也不证明自动文档抽取、专业判断、金额计算、Agent调查或处理模拟。

复现（选择新的输出文件名，已有完整报告不可覆盖）：

```powershell

.venv\Scripts\python.exe scripts/summarize_official_policy.py --report .local/reports/official-policy-new-run.json

```

完整报告存于本地；公开摘要只发布来源身份、哈希、数量与边界，不重新分发原始HTML或答案正文。历史`official-case-coverage.json`是采集器当时的结果，独立政策规则执行验收以本包报告为准。
