# 干净源码复现验收

此验收对应首版目标中的“别人能在本地复现数据、运行调查、检查证据及验证计算”。默认使用已提交源码，也可显式封存当前工作区；两种模式均使用全新依赖目录和空数据库，不继承原工作区账套、模型密钥或OCR/BGE模型。公开原件须通过独立参数提供。它不证明模型效果或真实企业业务有效性。

## 执行条件与命令

Windows上安装Git、兼容项目版本的Python、uv、Node.js和Chrome。`uv.lock`、`frontend/package-lock.json` 固定依赖；本验收显式使用 `uv --offline` 和 `npm ci --offline`，需要事先具备完整的项目缓存 `.cache/uv`、`.cache/npm`。已安装的 `node_modules` 不能替代缺失的包缓存。首次无缓存联网安装尚需独立验证。

```powershell
.venv/Scripts/python.exe scripts/validate_clean_checkout.py --output .local/clean-checkout-new

# 包含当前未提交源码，额外验收公开样例；不创建提交、不修改Git索引
.venv/Scripts/python.exe scripts/validate_clean_checkout.py --working-tree --public-archive .local/mof-vouchers-2025/digital-invoice.zip --output .local/public-checkout-new
```

输出目录必须不存在。脚本保留所有源码、安装日志、JUnit、浏览器报告、截图及失败证据，不自动清理或覆盖旧运行。测试会在新目录创建标注为合成的演示账套。占用临时回环端口，退出时只停止本次创建的服务，不停止原工作区服务。

## 验收步骤

1. 用 `git archive HEAD` 导出当前提交；未提交改动不会进入验收。记录提交、ZIP和验收脚本哈希，确认没有 `.env`、`.local`、`.cache`、`.venv`、`runtime` 和 `node_modules`。
   显式`--working-tree`时，改为封存Git已跟踪及未被忽略的新增源文件，保留工作区修改和删除。逐文件记录SHA-256，并在打包后及解压后核对。拒绝秘密环境文件、运行目录、依赖目录、链接或越界路径；`.env.example`作为公开配置模板允许进入。报告中的提交号仅标记基底，不声称未提交改动属于该提交。
2. 子进程环境只继承操作系统启动所需变量，不继承模型密钥、数据库、代理、OCR/BGE路径或可选测试开关；Python和npm从缓存按锁文件重新安装。
3. 执行后端全量测试、契约一致性检查及前端构建。可选依赖/真实数据/外部服务未启用时保留跳过原因，不将其计为已验证。
4. 在新目录生成480条原规则基准数据，运行规则评测及30条独立参考例；与原因调查v3的新封存集无关，不运行后者。
5. 再使用独立空目录和空SQLite数据库启动API，确认账套列表为空、任务模式为local、模型密钥未配置。启动独立Vite代理，运行默认网页测试。
6. 网页检查包含建账套、合成导入、规则调查、证据定位、隔离模拟、复核导出和迟到资料导致旧复核失效。真实OCR/BGE、BPI/年报数据的可选验收另见各自文档。
7. 显式`--public-archive`时，将该ZIP复制为单独输入，用新目录源码执行公开资料完整验收；采集器再次检查固定来源哈希，两XML示例分别投影，在另一套独立账库中执行45项API与16项网页检查。该输入不进入源码ZIP，也不会绕过原件校验。

`report.json`保存逐步状态、退出码、日志哈希及实测结果。任何一步失败，整体不得报告成功。这里的干净环境是新源码/依赖/应用数据目录；操作系统、浏览器与依赖缓存仍来自本机，不是全新虚拟机或远端CI。

## 已发现并保留的问题

- `clean-checkout-v1`：Python离线安装通过，npm项目缓存缺失pdfjs-dist包，返回ENOTCACHED；后续步骤没有执行。随后在Windows用户缓存找到该包，按锁文件SHA-512验证8,539,589字节，复制到项目缓存；没有联网或使用现成node_modules。操作记录为 `.local/clean-checkout-cache-repair.json`。
- `clean-checkout-v2`：两端离线安装通过；后端2001通过、40跳过、1失败（136.71秒）。Beancount“非固定版本须拒绝”测试只伪造版本号，仍读取真实可选依赖的元数据，因此在未安装Beancount的环境失败。修复为同时模拟版本和元数据，保留原有拒绝断言，没有安装可选包来掩盖问题，也没有改预期结果。
- README的v25、六条政策规则和旧测试数量已按当前代码与验收记录更新；历史模型负面结果保留。
