# OCR 表头切换边界修复

2026-10-13。修复同页多个表格之间错误继承列定义的问题，候选版本升级为 `ocr-table-candidates-v2`。候选仍需人工核实，不产生业务事实或自动入账。

## 问题与修复

前表具有“日期／编号／摘要／金额”时，v1会记住其列定义。后面出现“日期／编号／收入／支出”，由于缺少受支持的“金额”表头，旧代码没有识别为新表，继续把后续第四列800.00解析成通用金额。虽然没有绕过人工确认，但候选的列语义已经错误。

v2保留完整受支持表头的原处理。对于其余分组，若至少两段文字精确匹配支持的表头或已知不支持字段标签（收入、支出、借方、贷方、借方金额、贷方金额、余额、单价、数量），则停止沿用前表。该组以 `unsupported_header_boundary` 列入未归类区；后续文字保持未归类，直到新的完整受支持表头出现。普通数据行仅一个摘要值等于“金额”时，仍保持数据行，不当作边界。

这些标签只识别表格切换，不映射成新业务字段，也不根据旧列位置猜测含义。候选版本、表ID和候选ID相应改变，浏览器只接受v2响应，避免旧前端继续使用不同算法版本的候选。原OCR结果、人工复核与历史业务快照不修改。

用提交2388d47中的旧算法对**同一份实际OCR观察**离线回放，确实生成B102/800.00且copyable为true的错误候选；v2不生成该候选。这里只重放提取程序，不重新识别、不改原件或原OCR。旧结果保存为 `runtime/ocr-header-browser-v1/old-algorithm-mixed-header.json`。

原始API响应、页面截图、初次失败XML和后续成功XML全部保留；原件哈希、OCR摘要、候选回放、观察归属及手写预期重新核对通过，见[公开摘要](ocr-header-boundary-validation.json)。本轮为相关76项回归和三个网页场景，没有重跑全量测试或更改历史全量统计。没有新增依赖、模型下载或付费请求。

这仍是有限几何规则。无法覆盖所有错字、合并/多行单元格、旋转或未知表头；若两个普通单元格恰好都是表头词，可能保守地中断表格并要求人工处理。没有新增通用表格识别能力、真实票据准确率或专业业务有效性结论。
