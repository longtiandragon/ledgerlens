## 已跑通的限定闭环

两份原样投影均完成来源核对、上传、分录导入、借贷检查、重复导入和原文件下载；没有银行流水时资金核对能力仍为资料不足。

另建独立、明确标为教学资料的故障账套：

1. 显式教学科目映射：原材料→1403、进项税明细→2221.01、银行存款→1002。2221.01是本例自定义明细代码，不声称它来自原XML或国家统一明细表。
2. 人为增加一张完整重复凭证，并构造一条金额10,170.00、日期沿用过账日的教学发票观察。这些注入不是原文业务事实；原样记录、映射、故障行分别记录哈希与计数。
3. 实际FastAPI应用识别`DUPLICATE_INVOICE`，独立预期超额为10,170.00，运行确定性规则调查，保存当前快照内证据。
4. 仅在模拟分支反向冲销完整重复分录：借银行10,170.00，贷原材料9,000.00，贷进项税1,170.00。模拟余额回到原投影，目标重复规则消失。借银行表示恢复被重复减少的账面余额，不表示真实收到退款。
5. 故意遗漏税额冲销行的失败草稿也保留，判为不平衡且有违规项；不把错误草稿记作成功。
6. 保存明确写着“自动化教学记录、非人工专业签字”的保留意见，导出Markdown/JSON底稿。模拟、复核均不改原账。
7. 再增加独立教学迟到资料后，旧快照拒绝新复核（HTTP409）；历史证据不变，底稿保留并标为过期。

API闭环在独立子进程、全新SQLite中运行真实应用，强制禁用模型网关和外网连接；不依赖本机工作账库、密钥或预置成功结果。45项检查通过，v1、v2报告分别保留在`.local/reports/public-voucher-loop-v1/`、`public-voucher-loop-v2/`。这是API应用层验收，网页验收另列在[本轮摘要](public-data-closure-validation.json)，不得混算。

导入接口支持可选`synthetic`表单参数，网页可勾选“教学或模拟资料（非真实企业账簿）”；标记随原件保存并出现在证据和底稿中。对于明确声明财政部示例投影格式的JSON包，服务器会重新核对固定原件、分录、主体、字段定位及全部元数据，核验通过后强制保留教学标记，即使未勾选或提交`synthetic=false`也不会改变这一性质。来源文件列表统一显示“教学／模拟资料”，避免把公开原文示例误叫作自行合成数据。

改动原文或投影、缺失来源、使用未知投影版本、冒用官方示例，以及改变字段含义的重新映射，都会在写入来源文件和批次前拒绝；已存在的预览也不能通过重新映射绕过该约束。重传原样包仍可正常确认及下载。普通JSON/CSV等仍走原导入流程，未勾选不证明真实；移除示例格式声明的普通记录也不获得官方来源认证。该功能只核对两个固定教学原件的一致性，不是通用发票验真、真实性或税务资格判断。生产Docker构建已包含所需`datasets`模块，未引入新依赖。
