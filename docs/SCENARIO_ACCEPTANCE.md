# 首版场景包验收

日期：2026-10-24。范围：首版三个场景包（资金往来、采购费用、期间账表）各四种情况的产品流程验收。全部是手写的合成账套，没有调用模型；不代表真实企业数据、行业覆盖率或模型效果。

## 验收什么

每个格子是一份小账套，加上人在产品中依次执行的操作和每一步的预期结果。预期结果先按[产品需求](PRD.md)和规则定义手写，再运行产品比较；任何一步不符即整格失败，失败不改写成通过。每格都经过真实接口：导入 → 冻结快照 → 月结检查 → 调查（规则模式）→ 处理草稿 → 隔离模拟 → 补证与新快照 → 重新检查与接续 → 复核 → 底稿导出。

|场景包|正常|确定异常|资料不足|冲突或多解|
|---|---|---|---|---|
|资金往来|两笔付款合并入账另有退款：发生额及候选一致（正常观察），无需调整|手续费未入账：定位到未匹配流水，草稿需补对方科目，补齐后差异与未匹配都消除|只有流水没有银行存款分录：登记补证，补入分录后重新检查，原发现未再出现并生成接续核对案件|两笔等额付款对两笔等额分录：多种配对都成立，不自动核销，保留意见|
|采购费用|分批收货、分拆发票、分次付款：不判为重复确认|同一发票两张凭证全额确认：草稿冲回后入账的一张，原账不变|收货单未到：登记补证，迟到收货单导入后缺口不再出现并接续复核|同一发票号两份来源金额不同：不判重复，登记补证并保留意见|
|期间账表|期初加本期发生等于试算期末：不产生任何发现|凭证漏记一行：凭证不平且试算不衔接，补录遗漏行（科目必填）后两项都消除|试算表没有期初余额：不按零处理，补充期初后接续复核|业务日期与记账期间矛盾：同年迟到单据不调账；跨年差错在企业会计准则下须先认定重要性，在小企业会计准则下按未来适用法|

当前结果：12/12 通过，见[机器摘要](scenario-acceptance.json)（含每一步的预期与实际、源码版本与执行规则指纹）。

## 产品流程的连接

- **调查 → 处理草稿 → 模拟**：草稿由案件自己的发现和冻结快照确定性生成，模型或规则调查结论只作为参考附注，不改变分录。能确定的生成分录（如冲回重复确认），只能确定金额方向的留空必填字段（如漏记行的科目、手续费的对方科目），无法确定的不编分录、列出需要的资料。模拟时服务端重新计算草稿并比对，记录分录来自草稿还是人工、哪些字段由人补齐、哪些被改动。
- **模拟 → 发现对比**：每次模拟都在副本上重新检查，列出本案发现是否消除，以及已消除、仍存在、新引入的问题和正常观察。新引入的问题进入未决事项。
- **补证 → 新快照 → 接续**：重新检查时，同一规则且共享来源记录的新发现接续旧案件；上次的发现未再出现时，新快照上生成“接续核对”案件，供复核人核对补证记录后复核。系统不自动认定问题已解决，旧案件保持只读历史。
- **复核 → 底稿**：复核时冻结当时的未决事项和所依据的模拟方案；底稿导出接续关系、补证事项及其事件、处理草稿、每个模拟的来源与前后对比、当前未决事项和每条复核冻结的未决事项。

## 规则版本变化

执行规则升级为 0.2.0：月结检查在快照含银行流水时纳入资金核对结果，使其可以调查、模拟、复核和导出；银行流水未导入时只在能力清单中显示缺失，不生成猜测的差异。资金匹配中恰好由两个不相交候选合并而成的组合候选（如 60+40 对 60+40，与 60/60、40/40 并存）不再算作另一种解释；等额无法区分的配对仍报告多解。规则指纹变化后，旧快照须新建快照才能继续检查和复核，历史底稿照常可读。

## 复现

```powershell
.venv\Scripts\python.exe scripts/validate_scenario_packs.py --output .local\reports\scenario-packs-<日期>.json
.venv\Scripts\python.exe -m pytest backend/tests/test_scenario_packs.py backend/tests/test_case_flow.py backend/tests/test_treatment.py
```

验收脚本在新的临时目录和 SQLite 中运行，清空模型密钥，拒绝外网，报告只写新路径。浏览器用例 `frontend/tests/case-flow.spec.ts` 覆盖草稿模拟与复核、补证接续、资金差异补齐三条网页路径。

## 边界

- 账套是手写合成数据，每格一份，验证的是流程与判定口径，不是统计意义上的准确率。
- 处理草稿只覆盖能由快照确定的修正（冲回重复确认、冲减分拆超额、补录漏记行、补录未入账流水、冲回提前入账）；其他情况明确列出需要的资料。草稿不判断业务用途是否合法，模拟借贷平衡不等于处理合规。
- 冲突的两份来源都保留在只读原账中；当前版本没有作废来源记录的机制，冲突只能以补证记录和保留意见处理。
- 模型建议没有转成处理草稿（模型建议不自动成为业务事实）；“模型建议与模拟复核”的闭环效果评测仍未进行，AI 增益仍未证明。
- 未覆盖真实企业账套、税务、工资、合并报表等首版范围外的业务。
