# 原因调查 v4：确定性优先的混合方法（预注册）

> 2026-10-22 补注：封存运行已完成，预注册假设**未获支持**（T1、T2 未达成），结果见文末“封存运行与预注册分析”。以下预注册正文未改动。

更新：2026-10-20。状态：**离线实现与测试已完成；开发冒烟与封存运行尚未执行**。本文在任何 v4 模型请求之前提交，作为预注册设计；运行结果出来后在文末追加，不改动本节以上内容。

## 为什么做

v2、v3 两次封存测试中，单 Agent 都没有超过同预算确定性基线（v3：0.508 对 0.563，见 [ROOT_CAUSE_V3](ROOT_CAUSE_V3.md)）。v3 的逐类事后描述显示两者互补：

- 模型强在依赖文字线索的类别：作废重开 1.00 对 0，折让 0.80 对 0；
- 确定性方法强在需要解读补证资料的类别：错挂发票号、货物在途均为 1.00 对 0。

这只是事后观察，v3 封存集已用，不能在它上面验证。本轮在新生成的 v4 数据上预注册检验一个由此提出的假设：**确定性优先、模型兜底**的混合方法优于最强同预算确定性基线。

## 路由规则（固定于 `benchmarks/root_cause_v2_models.hybrid_route`）

只用可见资料与程序规则结果决定路由，不读真值：

|情形|处理|
|---|---|
|原因规则触发（`DUPLICATE_INVOICE` 或 `RECEIPT_GAP`），且固定补证得出确定类别|直接采用确定性结论，不调用模型|
|规则触发，但固定补证没有结论|补证额度已用掉；把补证结果交给单 Agent 作答，不得再补证|
|没有规则信号|单 Agent 按原流程调查，含 1 次补证额度|

依据：没有规则信号不等于证据证明业务正常。每案补证不超过 1 次，与基线的补证预算相同。模型部分沿用 `investigation-v27` 单 Agent 与窄契约，不改提示词。

按生成器语义手推，9 类情形中 4 类走确定性路由（重复入账、错挂发票号、单据迟到、货物在途），2 类在补证落空后交给模型（订单减少、无法判定），3 类没有规则信号（正常业务、作废重开、折让）。离线测试在开发、验证、封存三个划分的全部变体上确认了这一路由分布（只用可见与可请求资料，未读真值，未调用模型）。订单减少类在本设计下取不到决定性的订单资料，预计仍是弱项，这一点事先写明。

## 新数据（`datasets/generate_v4.py`）

- 270 例：9 个原因情形 × 3 个划分 × 10 个变体；沿用 v2/v3 的记账构造、原因与真值定义。
- 新的收货拓扑、金额偏移（58331）、命名空间 `rc4` 与 48 条新措辞；与 v2、v3 的措辞和拓扑均不重复（测试校验）。
- 措辞规则事先固定并由测试校验：验证集与封存集中，每个文字线索原因的 4 条措辞里恰好 2 条含该原因的 v2 关键词、2 条完全不含；任何措辞不含其他原因的关键词；正常业务备注不含关键词。这样关键词基线既不被偏袒，也不被完全排除。
- 局限：与 v2/v3 同一构造机制，且措辞由同一 AI 辅助作者在看过 v3 结果之后编写；不是独立的真实业务验证。

### 事后描述（非预注册，不改变上述结论）

关键词基线拿到满分，原因是案例抽取的偶然性：

- 每族入选 1 例。3 个文字线索类（订单减少、作废重开、折让）的入选案例恰好都含 v2 关键词。按“4 条措辞中 2 条含关键词”的设计，三类同时命中的概率约 1/8。
- 在完整 90 例封存集上零费用重跑三种确定性基线：仅规则 0.146、规则＋固定补证 0.563、关键词补证 **0.848**（结论 91.1%，决定性补证 46/60）。报告 `root-cause-v4-sealed-baselines-full-posthoc.json`，SHA-256 `36b5f8bd…3968e1c2`。
- hybrid 没有在 90 例上运行，因此不能据此推断它会高于关键词基线。这一观察只作为下一轮设计的依据：封存样本需要更多案例，或按措辞类型分层抽取。

### 局限

- 合成数据，数据、措辞与真值由同一 AI 辅助作者编写，不能外推为真实账套效果。
- 封存集只有 9 个场景族，每族 1 例；区间宽，对“比基线略低或略高”的区分力不足。
- 费用为列表价估算与余额差，不是账单。
