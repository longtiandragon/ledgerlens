# AI 模拟首次使用试用（2026-10-22）

**性质**：这是 AI 编程助手（Claude Code）扮演“第一次接触本项目的评委”所做的模拟试用，**不是真人用户试用**，不能代替会计从业人员或真实用户的反馈。比赛要求全程 AI 辅助开发，可用性验证也由 AI 完成，因此方法、过程和发现的问题都完整记录在这里。

## 方法

- 从 GitHub 公开仓库全新克隆，只照 README 首屏的命令和说明操作，不使用仓库内部知识。
- 在真实 Chrome 中逐步操作，每一步都截图查看：演示账套的完整流程，再加一项 README 以外的操作，即导入一份按常见格式自制的凭证 CSV（[judge-voucher-export.csv](trial/judge-voucher-export.csv)，含一笔故意重复的入账）。
- 发现问题后修复、补测试，再从新的克隆复测。复测流程已固化为脚本 [`scripts/first_use_walkthrough.cjs`](../scripts/first_use_walkthrough.cjs)，导入场景另写成 CI 网页用例 [`first-use-own-data.spec.ts`](../frontend/tests/first-use-own-data.spec.ts)，每次提交都运行。

## 复测（main `0dc13d4`，新的克隆）

`start-local.ps1` 启动后 90 秒就绪（本机已有依赖缓存；无缓存的首次安装会更慢）。走查脚本 10 步全部通过，页面错误 0：

- 建账套、载入演示、月结检查、规则调查都正常；
- 切换到“浏览证据”后回到页顶；
- 模拟冲回、保存复核（时间标 UTC）都正常；
- 迟到收货单使旧复核失效；
- 自制凭证 9 行全部进入预览，0 错误。推导字段为：记录类型、会计期间、来源编号各 9 行，贷方 4 行、借方 5 行补 0。确认后导入。
- 导入后检查出 3 项：
  - 演示数据中的“发票重复确认”；
  - 自制数据中故意重复的发票 FP20260903，报为“一票多凭证核实 · 证据不足”；
  - 科目 2221 不在账套的科目范围内，报为“科目未映射”。

## 仍然存在的局限

- 只试了 Windows 本机方式。Docker 与 Linux 方式由 CI 每次提交按 README 原样执行，macOS 没有实测。
- 导入只覆盖常见表头，金蝶、用友等软件的原生导出格式没有逐一实测；科目只按编码匹配。
- 这次试用验证的是“能否走通、提示是否看得懂”，不能说明会计判断是否正确。那需要专业人员复核，见 [docs/review-kit/short/](review-kit/short/)。
