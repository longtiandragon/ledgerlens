# 检索无答案阈值实验

## 预注册设计（2026-10-13，尚未查看本批检索预测）

问题：仅依靠检索首位分数能否在保留正确条文的同时，拒绝语料没有答案的问题？这不是会计结论或条文适用性判定。产品默认方法和此前20查询结果不变。

新增48条实现者手写查询：开发24条、留出24条，各有12条可回答及12条无答案。每份可回答集合覆盖六份原文、每份两条，开发与留出使用不同条文锚点，也不复用旧20查询的原句。每份无答案集合含6条缺少企业私有资料的问题、6条语料范围以外的问题。真值含手选来源及完整锚点，与运行查询分文件，均先保存再计算预测。数据不是独立专家标注或真实用户样本，不能据此完成专业验证目标。

沿用已核验六份原文、固定BGE小模型、480-token窗口/400步长及前6条检索。关键词与BGE使用同一批窗口和制度过滤。Docker启动尝试后未就绪，因此BGE本轮使用本地NumPy逐段精确余弦排序；没有将它记作实际pgvector验收，不更改生产持久索引。

候选拒答方法仅判断首位分数是否大于等于阈值；通过则保留原前6条，否则全部不返回。相似度不是概率。不引入交叉编码器、远程模型、规则答案或模型生成标注。

开发集阈值选择规则提前固定：候选为各不同首位分数及略大于最大分数的一点；最大化可回答/无答案两类平均正确率。并列时依次选择更少无答案误接纳、更多正确条文保留、较低阈值。完全同分的查询不可按真值拆分。程序故障留在分母中，不能计为正确拒答，开发查询故障则停止校准。

先保存两个集合全部预测，再读取开发真值，保存阈值文件后才读取留出真值。留出集只作这次最终比较，不根据结果改阈值、查询或答案。固定候选门槛同时要求：24条全部成功、无答案误接纳至多1/12、保留正确前6命中至少9/12、相对原排名损失正确命中至多1条。即使通过也不自动接入产品，需更多数据和独立专业复核。

计划、源码和输入哈希见 [retrieval-abstention-plan-v1.json](retrieval-abstention-plan-v1.json)。合成分数的11项回归已通过（0.40秒），覆盖同分、程序故障不得冒充拒答、接受错误片段不得算命中、拒绝全部不满足覆盖门槛和输出禁止覆盖；Ruff通过。

## 复现

```powershell
.local/retrieval-env/Scripts/python.exe benchmarks/reference_abstention.py --plan docs/retrieval-abstention-plan-v1.json --corpus .local/retrieval-corpus-v1.json --registry docs/retrieval-sources-v1.json --source-root .local/retrieval-sources-v1 --model-root .local/bge-small-zh-v1.5 --output .local/retrieval-abstention-new
```

输出必须为新目录。原文、模型与依赖沿用 [RETRIEVAL_VALIDATION](RETRIEVAL_VALIDATION.md) 已核验的本地文件与许可证，不下载、不付费。失败保留报告，不把已失败目录覆写成成功。
