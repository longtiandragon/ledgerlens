## 参考程序算术重放

`backend/app/financial_math.py` 自主实现有界算术DSL，只支持10个具名操作、先前步骤引用和明确常量。它不执行Python，不读取文件或模型，不用生产函数生成答案。使用Decimal精度50，金额与输出均为字符串；未知格式、缺失、歧义和非法运算明确拒绝，不补零。

`benchmarks/finqa_program_replay.py` 将官方参考程序及对应表格交给计算器，评测器随后与独立保存的官方 `exe_ans` 比较。参考操作语义来自 [FinQA官方评测器](https://github.com/czyssrs/FinQA/blob/main/code/evaluate/evaluate.py)，没有复制其浮点计算实现。

|---|---|---|---|---|
|financial-math-v1|866/883|866|17|0|
|financial-math-v2|880/883|880|3|0|
|financial-math-v3|883/883|883|0|0|

首次失败涉及前导小数点、带重复格式的数值单元格和中间除法近似的后续运算。修复解析与精度元数据，没有修改参考程序或答案。重复格式仅在数值一致时接受；相互矛盾的值拒绝。非整除结果保留舍入标记，后续计算继承；不可确定的精度敏感比较拒绝。全部历史报告留在本地，公开摘要见 [v3重放结果](finqa-program-replay-v3-summary.json)。

**883/883验证的是“给定正确程序时，计算器能否计算”，不包含模型读题、抽取、公式选择或会计业务判断。** Decimal与上游二进制浮点语义不同，当前外部答案在5位小数比较下均一致，不能承诺任意数据完全一致。

## 只读文档的真实模型试跑

`benchmarks/finqa_models.py` 只将当前观察文档交给DeepSeek，模型自行输出有界程序和来源编号。运行模块不打开参考程序、答案或检索标签；评测器只在模型运行结束后读取外部答案。样本按可观察ID的固定SHA256排序选取，不按答案或操作类型挑选。

首轮32题已全部运行，48次物理请求、85597 Token：20题通过程序及来源校验，12题输出校验失败；9题与外部答案一致，全部32题计入准确率为28.125%。模型非思考模式、每题最多3次请求／40000 Token／一次修复，全批最多96次请求。原始报告 `.local/reports/finqa-model-pilot-v1.json` 与失败记录保留；[公开试跑摘要](finqa-model-pilot-v1-summary.json)不包含原文、参考答案或私有推理。

累计出现25次程序语法诊断、2次操作数来源诊断和1次结构诊断，包含之后修复成功的输出，不能当作28道失败题。20题通过校验中的11题仍与外部答案不符，说明程序合法、引用存在不能保证公式和尺度正确。失败不会从准确率分母删除。按保存的官方列表价格估算全部48次已知请求为USD 0.009610848–0.019221696，不是提供方账单。样本只覆盖公开dev的一小部分，不代表883题或会计业务准确率。

`financial_evidence.py` 在当前文档内定位每个普通操作数的原文字符区域，表格运算保存真实行列。常量与中间结果另列；百分数区分比例与百分点。不允许通过假引用或别的文档数字通过校验。**数值确实出现不证明选对了年份、单位或公式；来源定位状态与语义状态分别保存。** 当前计算器及模型试跑属于评测组件，尚未注册为产品调查Agent工具或自动转成业务事实。

新增70项回归覆盖独立Fraction参考、缺失值、重复表格标签、代码注入、前向引用、精度标记、来源作用域、答案分区、一次修复、费用保留和重复启动拒绝；最近完整后端847项通过（73.30秒），API契约及静态检查通过。没有新增运行依赖。

## 复现

以下重放不调用模型，输出文件必须使用新名称，避免覆盖历史结果：

```powershell
.venv\Scripts\python.exe -m benchmarks.finqa_program_replay --help
.venv\Scripts\python.exe -m benchmarks.finqa_models --help
.venv\Scripts\python.exe -m pytest backend/tests/test_financial_math.py backend/tests/test_financial_evidence.py backend/tests/test_finqa_models.py -q
```

真实模型试跑需本地后端配置，必须限制样本及物理调用预算。API超时可能已经计费，保守预留与已返回用量分开；现有报告拒绝再次启动，不在观察超时后重复派发付费工作。
