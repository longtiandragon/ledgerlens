# 年度报告报表数字组件：真实样例与30份本地探查

现有 `pdfplumber 0.11.10` 对下列三份 2025 年文本 PDF，依据**真实表格行、合并报表节边界和本期列头**定位资产总计、负债合计及全部所有者权益合计。首轮 **3 份 observed、0 份 rejected**，九个总额与另一条只读抽取及六个原 PDF 页面渲染逐项核对一致。随后扩展全部30份本地年报，网格修复阶段为22/8；当前有界跨行标签版本为 **23份 observed、7份 rejected、0份未探查**。四份固定原件有独立单元格回归，其余19份观察没有独立金额答案。Observed只表示生成了带定位的抽取记录，不是财务准确率。

本组件先评估报表数字提取，再接入[独立只读年报工作台](STATEMENT_WORKSPACE.md)。未修改运行 Agent、财务规则、规则覆盖或任何模型评测结果。没有新增依赖、网络请求、OCR 或模型调用。`benchmarks/annual_statement_probe.py` 产生的是带证据位置的观察记录，不是自动生成的标准答案。

## 具体技术设计

组件应分为来源身份、节上下文、列映射、行匹配、金额规范化和独立评测六个步骤。每一步失败都输出可区分状态，不能用模型猜测、算式补数或跨表借数据完成结果。

1. **固定输入快照。** 来源必须绑定公司、报告年度、PDF 哈希、来源 URL 和解析器版本。原件只读；每次解析的字节必须与声明哈希一致。当前探针只接受三份明确样例，未来扩大范围时才逐份增加支持证据。
2. **固定合并节边界。** 以先前文档筛查的页码作搜索入口，再重新确认独立“合并资产负债表”表头。用文本行坐标限定起始表头至下一独立报表表头，最多扫描五页。日期、单位、列头和金额行都须落在同一节内；同页后半部的母公司日期或单位也不能作为合并上下文。缺单位、日期或节终点均拒绝。
3. **明确本期金额列。** 首表解析实际列头，按明确的 `2025年12月31日` 对应列定位。苏宁的符号列头必须同时具有该节内的期末日期。续页有重复列头时重新映射；没有时继承最近有效合并列头，并核对四列结构与金额列的横坐标。不能假定“第一个数字必然是本期”，也不能继承母公司列头。多重合并/母公司交叉列、未知日期排列和不同列数目前拒绝。
4. **表格单元格绑定标签与金额。** 对有线框的三份样例使用 `find_tables()` 和表格行单元格；只清理标签单元格内部空白/换行，再完整匹配“资产总计”“负债合计”“所有者权益合计 / 所有者权益（或股东权益）合计”。“流动负债合计”“归属于母公司所有者权益合计”和“负债和所有者权益总计”均不是这些目标标签。每项必须恰有一行，否则拒绝。表格法恢复用友与金山的多行权益标签，比全文三行窗口更适合该任务。
5. **保留原单位并精确转换。** 原始单元格文本、清除千分位后的 `Decimal` 字符串、原币种/单位、报告期、本期/上期金额、页码、表/行、行及金额单元格边框、原文本行均保存。当前只支持明示人民币元或千元；千元转元乘以整数 `1000`，不使用浮点金额。如果转为元需要额外四舍五入则拒绝。换算只转换原报表已披露的精度，不创造未披露的精确金额。
6. **观察与真值分离。** 探针记录 `status: observed/rejected`。即使内部算式吻合，也不把观察记录标为财务标准答案。未来评测真值须由独立标注流程提供，并保留原证据与审核记录；运行 Agent 和生产计算不得读取评测真值。

## 已出现的歧义与拒绝边界

苏宁 2025 年总权益为 `"10680549"` 千元，归母权益为 `"12631961"` 千元；用友总权益为 `"9247958304"` 元，归母权益为 `"7598565044"` 元。金山当期归母权益与全部权益恰好同值，但上一年度不同，因此值相等不证明选中了正确标签。当期少数股东权益单元格为空，也不把空白当成业务事实零。

原三份样例都有可读文本和线框。旧版本全部30份探查后的8项拒绝包括未确认完整币种/单位、合并与公司多层表头以及目标标签拆成多个物理单元格。当前跨行支持消除永辉2023这一项，其余7项继续拒绝。无文本、扫描版、无线框且无法绑定金额行、混合单位、重复目标、缺失本期列、单位/报告期冲突、表格列几何未确认等情况继续明确拒绝。OCR 没有实现，不会以猜测替代。

现有 `datasets/annual_reports.py` 仅筛查文档身份及基本报表位置；`backend/app/imports.py` 的 PDF 导入仅返回逐页文本，不具备本组件的金额、单位和合并列解释能力。独立年报页面可以浏览未复核观察；接入账务判断或运行 Agent 前仍需要独立组件回归和人工真值审核。

## 独立验证方案及本次检查

不能仅依据资产 = 负债 + 权益评价抽取准确性，因为同时取到母公司三项、上期三项或错误但相等的权益标签，也可能账平衡。当前三组按原单位计算的差额分别为 `"0"`、`"0"`、`"0.00"`，只是算术一致性信息。

建议把独立审核真值固定为“原件哈希 + 公司 + 报告期 + 合并范围 + 单位 + 标签 + 原单元格 + 实页/行/列位置”，由不使用组件输出来生成答案的人工标注者从原 PDF 逐格录入，第二人复核。抽取结果与真值分别存储；字段相等、标签范围、列头、单位换算与证据位置各自比较。评测应统计已支持、明确拒绝、错位、错值和证据缺失，不能只在成功样例上报准确率。

扩展到 30 份前，至少补独立手写或人工标注负例：同页合并与母公司、归母与总权益同值/异值、2024/2025 列顺序交换、多层“合并及公司”列头、元/千元/未知单位、单位跨页改变、跨行标签、表格线缺失、金额空白与括号负数、重复目标、过长节、PDF 哈希改变、扫描页。禁止用生产解析器的输出创建标准答案或修改真值迁就实现。

三个实际样例的独立抽取与六页图像核对首先固定为47项回归。网格修复阶段为54项回归；当前 `backend/tests/test_annual_statement_probe.py` 为 **76项通过、0 skipped**：72项独立手写输入或机制检查，以及4份固定原件的本地回归。跨行样例原文和新增测试见[说明](ANNUAL_SPLIT_LABEL.md)。手写输入覆盖合并节缺单位/日期而同页母公司提供这些信息、首表前上下文、本期/上期逆序、同页母公司列头隔离、归母与全部权益同值/异值、全部权益缺失、重复总额、元/千元精确换算、括号/全角负数、金额空白与非法千分位、列几何缺失、原件改变/越界、无文本页及CLI失败统计。新增全清单选择、重复身份拒绝、历史失败报告不覆盖、空网格槽与真实空值区分、上期列坐标及原始列索引测试；没有改变人工金额答案。

三份真实回归分别固定此前独立转录与图像核对的原哈希、九个本期与九个上期金额、单位、报告期、物理页码、页内文本行和表格行，并核对原字节未被改变；期望值是测试中的人工观察常量，不读取探针结果来生成答案。其它环境缺少清单、所选记录或原 PDF 时可明确 skip，绝不下载补齐；原件已存在但哈希或值改变时测试失败，需要独立复核新快照，不能直接重写期望值。

回归首轮为 44 passed、3 failed，发现并修复两处实现缺陷：续页独立一行的“币种：美元”此前被忽略，现在在合并节内单独核对币种；本期或上期列缺少坐标此前触发 `TypeError`，现在明确拒绝为 `column_header_geometry_not_confirmed`。拒绝预期保持不变，修复后 47 项全部通过。先前跨节借日期/单位问题也继续由独立负例防护。探针与新测试的 Ruff 检查通过；这些是三个已审核样例的复现和局部回归，尚未建立覆盖 30 份报表的财务准确率评测，也不新增规则覆盖或运行 Agent 接入。

## 复现

```powershell
.venv/Scripts/python.exe -m benchmarks.annual_statement_probe
.venv/Scripts/python.exe -m benchmarks.annual_statement_probe --all-local --output .local/annual-statement-probe/fresh-all-local.json
.venv/Scripts/python.exe -m pytest backend/tests/test_annual_statement_probe.py -q
.venv/Scripts/python.exe -m ruff check benchmarks/annual_statement_probe.py backend/tests/test_annual_statement_probe.py
```

探针只读原件，观察 JSON 和渲染图位于 Git 忽略的 `.local/annual-statement-probe/`。出现任何拒绝时保留 `rejected` 与错误原因，CLI 返回非零；它不会向运行 Agent 提供事实、写入规则覆盖或调用外部模型。

已存在的输出拒绝覆盖，复跑须使用新的`--output`名称。结果绑定解析源码和来源覆盖清单的哈希，不能把旧报告标为当前实现的验收。

## 30份实际运行与失败保留

首轮全量结果存于`.local/annual-statement-probe/all-local-v1.json`：22份产生三项总额、8份拒绝。之后修复了pdfplumber合并网格中“无物理单元格且无文字”的槽位处理，保留原始列索引，并同时核验上期列坐标和原文。真实空值仍拒绝，非空文字缺坐标仍拒绝；不会删空值后将另一个年份金额移过来。新运行保存在`all-local-v2.json`、`all-local-v3.json`，没有覆盖原记录。

|年度|探查|observed|rejected|
|---|---:|---:|---:|
|2023|10|6|4|
|2024|10|8|2|
|2025|10|8|2|

8项拒绝：红旗连锁及广联达三年各3份未能在当前合并节确认完整币种/单位；苏宁2023的合并及公司组合表头未支持；永辉2023的网格空位修复后能读取部分总额，但跨单元格的完整权益标签仍未确认，保留`required_total_missing_or_duplicate`，不通过资产减负债补出权益。

首轮后三项代表版式的原页已渲染检查。6份报告不能仅凭中国企业身份推断币种；组合表不能按“前两列看起来正确”自动确认合并列。当前22份都通过内部资产平衡，这是辅助算术信息，不证明范围、年份、数字或会计语义准确。19份新增observed没有独立冻结金额答案；不能将22/30宣传为正确率。公开元数据见[探查覆盖](annual-statement-component-coverage.json)，原文及完整定位仍留本地。
